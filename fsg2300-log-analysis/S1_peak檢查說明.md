# S1 Peak 檢查說明

本文件說明 FSG2300 Log Analysis Web 中「S1 peak檢查」的用途、操作方式與判定邏輯。

目前版本：v1.9.2

## 目的

S1 peak 檢查用來從大量 Wafer Log 中快速找出 S1 Loading 異常變化，尤其是：

- S1 Loading 突然跳升
- S1 Loading 在一段拉升過程中斜率偏高

這個功能不是只找最大 peak，而是針對 S1 Loading 的變化型態進行過濾。

## 操作流程

1. 按「S1 peak檢查」。
2. 選擇要檢查的資料夾。
3. 系統會搜尋該資料夾與子資料夾內的 `Wxxxx.csv`、`Wxxxx.ini`。
4. 檢查完成後，畫面會顯示總晶片數與異常筆數。
5. 點選結果表格中的任一列，下方會顯示該 Wafer 的 S1 Loading 圖。
6. 若需要報告，按「產出 PPT」輸出 S1 peak 異常報告。

## 設定項目

### S1負載差異值

用於「急升」判定。

系統會比較目前點與前一個有效點：

```text
差異 = 目前 S1 Loading - 前一點 S1 Loading
```

若差異大於設定值，且同時符合雜訊過濾條件，就列為「急升」。

差異在設定值以內會略過。

### S1整段拉升斜率

用於「整段拉升斜率」判定。

系統會先對 S1 Loading 做平滑化，並找出真正開始拉升的位置，再計算整段上升斜率：

```text
斜率 = (End S1 Loading - Start S1 Loading) / (End 秒數 - Start 秒數)
```

若斜率大於設定值，就列為「整段拉升斜率」。

## 檢查邏輯

### 1. 取得有效 S1 Loading 資料

系統會從 G1 / G2 step 資料中取得 S1 Loading，並只保留有效數值。

圖表時間會轉成相對時間，從 0 秒開始顯示。

### 2. 排除 S1 加速過程

S1 剛開始轉速尚未穩定時，不做異常判定。

判斷方式優先使用 S1 轉速：

- 若 S1 speed 尚未達穩定轉速，視為加速中。
- 加速中資料不列入異常判斷。

若資料中沒有足夠的 S1 speed，會改用 S1 Loading 變化估算加速區段。

### 3. 急升判定

急升判定是看「前值」而不是跟整段 peak 比較。

```text
目前點 - 前一有效點 > S1負載差異值
```

符合條件時，表格會顯示：

- 秒
- S1 Peak
- 基準
- 差異
- 斜率
- 判定：急升

圖表會用紅色圓圈標示該異常點。

### 4. 整段拉升斜率判定

整段拉升斜率不是取單一 peak，也不是任意最低點到最高點。

目前邏輯為：

1. 先將 S1 Loading 平滑化。
2. 找出低點附近的候選區。
3. 從候選區往後找「負載準備開始拉升」的位置。
4. 確認後方短時間內有明顯抬升。
5. 使用該 start 到 end 的整段資料計算斜率。

start 點會盡量避開前面平坦區或雜訊低點，改從負載真正準備開始拉升的位置起算。

### 5. 圖表標註

若判定為「整段拉升斜率」，圖表會顯示：

- start 點紅色圓圈
- end 點紅色圓圈
- start 到 end 的紅色虛線
- 箭頭指向 end 端

若判定為「急升」，圖表只會在急升點顯示紅色圓圈。

## 結果欄位說明

| 欄位 | 說明 |
| --- | --- |
| 所在資料夾 | 異常檔案所在資料夾 |
| 檔案 | Wafer 檔案名稱 |
| Wafer | Wafer 編號 |
| 站別 | G1 或 G2 |
| Chuck | Chuck 編號 |
| 結果 | 原始 Log 判定結果 |
| 秒 | 異常點發生時間 |
| S1 Peak | 異常點的 S1 Loading |
| 基準 | 用來比較的起始或前值基準 |
| 差異 | S1 Peak 與基準的差 |
| 斜率 | 負載上升斜率 |
| 判定 | 急升或整段拉升斜率 |

## PPT 輸出

按「產出 PPT」後，系統會輸出 `.pptx` 報告。

PPT 內容包含：

- S1 peak 檢查摘要
- 異常列表
- 每筆異常的 S1 Loading 圖表
- 斜率異常的 start / end 圈、紅色虛線與箭頭

大量異常資料輸出時，系統會先開啟儲存檔案視窗，再開始產生 PPT，避免瀏覽器封鎖儲存動作。

## 注意事項

- S1 peak 檢查結果會受設定門檻影響。
- S1負載差異值設定太低，可能會抓到較多雜訊。
- S1整段拉升斜率設定太低，可能會抓到平緩上升段。
- 建議先用已知異常批次調整門檻，再套用到大量資料。
